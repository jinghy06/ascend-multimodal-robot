# SmolVLA 延迟优化与资源实测

2026-10-20，同一 Atlas 200I DK A2 / Ascend310B4，沿用独立 Python/CANN 测试环境。没有控制机器人，也没有修改原始基础测试脚本与权重。

## 结论

- 保持三相机、512×512 和 10 步去噪时，当前纯运行时改动仅将同轮暖机结果从 4.228 s 降至 4.168 s，约 1.4%，该样本的完整输出逐元素一致。不能把如此小的差异视为稳定的大幅加速。
- 同样三相机和分辨率，改成 5 步去噪约 3.497 s；相对原动作块 L2 差异约 7.29%。这是输出差异，不是“抓取准确率下降 7.29%”。
- 单相机、256×256、3 步去噪测得约 0.680 s；单相机、256×256、5 步约 0.915 s。这些改变了输入条件和积分精度，当前权重下与原配置输出差异很大，应作为后续按该配置微调和验证的候选，不能直接宣称抓取效果可用。
- 三相机合批编码约 4.190 s，没有提速，且测试内存压力更大，因此未启用为默认。

默认复现入口保留三相机、512×512 和 10 步。快速配置必须明确指定参数。本次没有实现 0.68 s 与原动作数值等价，也没有实现完整机器人闭环控制。

## 主要耗时

暖机后基线约 4.197 s 的分段同步采样中：

| 部分 | 观测耗时 |
|---|---:|
| 三路视觉编码合计 | 2.373 s |
| 10 次动作去噪合计 | 1.367 s |
| CPU 图像预处理 | 0.031 s |
| 时间/动作后缀嵌入合计（已包含在去噪内） | 0.034 s |

嵌套阶段不可相加；同步测量本身也会改变调度。瓶颈主要在视觉编码，单纯减少去噪步骤无法解决全部延迟。

## 已执行的改动

1. 预先构造与原实现相同的 FP32 Euler 时间网格，用 Python 固定循环代替逐步读取 NPU 标量作为 while 条件。
2. 缓存小型、与当前观测无关的正弦时间嵌入，避免每步将 NPU 时间标量复制回 CPU。按去噪步数与 batch/device 分开缓存。
3. 每次推理重新计算当前图像、语言、状态和前缀 KV，不跨观测复用旧视觉特征。测试没有通过跳过当前图像处理来制造低延迟。
4. 分别测量减少去噪、缩小分辨率、减少相机和合批视觉。合批无收益；改变工作配置的方案与纯运行时方案分别记录。

`optimize_runtime.py` 面向当前单策略、单工作线程。不要在同一进程并发调用多个策略；若集成到 ROS 服务，应由一个串行推理工作线程持有策略。只缓存时间嵌入，不会替代现场观测。

## 独立进程复测快速配置

使用新入口 `run_optimized.sh --cameras 1 --resolution 256 --steps 3 --runs 5`，重新启动进程与加载模型：

- 导入和加载模型：75.41 s。
- 首次前向暖机：17.9402 s。
- 后续 5 次使用不同噪声种子（43～47），耗时 0.6777～0.7139 s，中位数 **0.6801 s**。
- 六次输出均为有限的 `[1,50,6]`。首次 seed 42 的全部输出与 tuning 阶段同配置逐元素一致。
- 独立快速配置测试期间整机可用内存最低 424.60 MiB，swap 已用最高 1249.00 MiB，包含加载阶段；不能据此推定完整 ROS/YOLO/语音并发时的占用。
- 测试完成后没有遗留模型或监控进程，NPU Health OK。原始动作块与内存采样已打包为 `raw-results.tar.gz`。

这是少量合成观测的运行验证，仍不是多场景尾延迟或抓取效果评测。


## 内存、存储与多任务

- 系统可见内存 3513 MiB，空闲时可用约 2.9 GiB；根分区尚余约 20 GiB。安装轻量推理程序有存储余量。
- core 测试期间（包括导入、加载和推理）整机可用内存最低 404.45 MiB，swap 已用最高 1264.25 MiB。
- tuning 阶段最低可用 422.86 MiB；合批实验最低可用约 321.70 MiB。这些压力峰值不等于稳定模型占用，也不代表所有配置同时运行。
- 新测试进程峰值 RSS 约 2.2 GiB，和整机共享内存/缓存不能直接相加；不能只用权重文件大小预算运行内存。

可行方向是让跟随检测、完整导航、SmolVLA、自由对话按阶段调度，保留独立急停/必要避障/底盘控制。全部模型常驻尚未验证，不应承诺流畅。按需退出进程可以释放资源，但原环境模型加载约 72 秒，首次前向还会有初始化开销，所以应在进入抓取阶段前提前加载，连续完成多次抓取后再释放。

详细工作阶段、语音回应与激光点导航方案见 [系统资源方案](系统资源方案.md)。目前没有安装完整 ROS/YOLO/ASR 并发系统，不能给出它们的本机实测内存总量。

## 复现

模型与虚拟环境沿用板上 `/root/smolvla-test-20261020`，新脚本目录为 `optimization-v1`。

```bash
# 保留原工作配置；首次暖机，随后记录 5 次推理
bash /root/smolvla-test-20261020/optimization-v1/run_optimized.sh --runs 5

# 仅减少去噪步骤：输出会变化
bash /root/smolvla-test-20261020/optimization-v1/run_optimized.sh --steps 5 --runs 5

# 实验性低延迟工作配置：需要匹配配置微调与抓取验证
bash /root/smolvla-test-20261020/optimization-v1/run_optimized.sh --cameras 1 --resolution 256 --steps 3 --runs 5

# 重跑阶段对照；顺序执行，避免模型进程同时加载
bash /root/smolvla-test-20261020/optimization-v1/run.sh --phase core
bash /root/smolvla-test-20261020/optimization-v1/run.sh --phase tuning
bash /root/smolvla-test-20261020/optimization-v1/run.sh --phase batch
```

每次 `run_optimized.sh` 产生独立 `inference_日期时间` 目录保存 JSON 和每组原始动作；阶段对照会覆盖对应 `results_*` 目录。原测试结果仍保留。

## 适用边界

这里的耗时是模型已加载后、输入图像已在内存中的完整策略调用，包含 CPU 预处理、辅助计算和同步；不包含相机曝光、ROS 传输、麦克风识别、任务切换加载、机械臂通信和电机执行。0.68 秒模型推理不等于 0.68 秒抓取，也不等于整机控制链路已达到同样延迟。

下一阶段若要采用快速配置，需要在最终相机数量与分辨率下采集/微调，使用真实观测测试多个物品位置并测量闭环抓取。若要求保留原工作配置同时进一步明显提速，需评估静态图/OM、算子融合或更底层推理后端；本轮未完成这些迁移，不能承诺其速度。
