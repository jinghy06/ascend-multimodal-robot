# SmolVLA 语言骨干复用检查

2026-10-20。直接使用本板已经下载的 `lerobot/smolvla_base`，不另载 Qwen，不下载第二套模型权重。

## 确认的结构

- 标准策略的对外接口输出动作，但内部对象是 `SmolVLMForConditionalGeneration`，可以单独访问其文本生成入口。因此“标准策略不输出文字”不等于“内部语言能力绝对不能复用”。
- 当前 checkpoint 包含 16 层语言 Transformer、词嵌入、最终归一化和 `lm_head.weight`。输出头形状为 `[49280,960]`，不是缺失或随机新建的头。
- 原始骨干配置是 32 层；本次 SmolVLA 配置只保留前 16 层。当前裁剪版不能默认具有完整原版的对话质量。
- 权重中已有 16 个语言层的 BF16 文件总大小约 300.06 MiB。这不包含词嵌入、输出头与视觉编码器，也不等于实测运行内存。

结构依据：[LeRobot v0.3.3 实现](https://raw.githubusercontent.com/huggingface/lerobot/v0.3.3/src/lerobot/policies/smolvla/smolvlm_with_expert.py)。原始骨干[模型卡](https://huggingface.co/HuggingFaceTB/SmolVLM2-500M-Video-Instruct)标注主要语言为英文，中文自由对话能力也需单独验证。

## 接出的生成路径

使用已有 `policy.model.vlm_with_expert.vlm.generate()` 与同一分词器/聊天模板。没有为问答构建第二个大模型。修正运行时层数元数据以匹配实际 16 层，使用 eager attention。NPU 路径遇到生成位置索引和 FP32 RoPE 的兼容问题，因此将小型位置范围、因果掩码与 RoPE 计算移到 CPU；不修改磁盘权重或全局 Transformers 源码。

测试：一条英文算术、一条中文算术和一条中文自我介绍；贪心生成，最多 32 个新 token。该测试只能初步发现明显不可用输出，不能作为全面问答评测。

## 实测结果

NPU 生成入口已跑通，未加载 Qwen 或新增模型权重。CPU FP32 对照也完成，三条问题各生成 32 个 token；每条的全部 token ID 在 CPU 与 NPU 上逐个一致。因此本组异常不是只发生在 NPU 的数值/适配问题。

|---|---|---:|---:|
| What is 1 + 1? Answer briefly. | `oriouslylysorohsometitelescopeaconciliationistone- strenglestreirlyestoneousnessphinxsouthernityelescopeophieob` | 22.20 | 11.50 |
| 请用中文回答：1加1等于几？ | `�anitatifatronicsityopoliticalitresonritectiarchscoreiconciliationistimitpanamInitenorialssoutheasternity` | 21.12 | 4.61 |
| 请用中文简单介绍一下你能做什么。 | `negieorifatimorgetownitunesoneofstatewideity-\|\|-numerableitcoinworldoampamityopoliticaliternlportoocalyooh` | 21.31 | 4.60 |

三条回复均没有回答问题、也未形成可理解的正常回答。**当前裁剪权重在这组最基本的测试下不能承担自由对话。** 这不是对所有可能提示词的全面评测，也不能单凭本次测试认定裁剪层数是唯一原因；但它足以说明不能直接把当前策略权重作为现成的自由问答模型。

注意：表内英文问题是第一次生成，含暖机开销。CPU/NPU 的运行时精度、兼容处理不同，表内时长不能用作通用模型性能基准。完整输出、原始 token ID 和异常历史见同目录 JSON/日志。

复现：

```bash
# 两个完整模型不要同时加载
bash /root/smolvla-test-20261020/shared-language/run.sh --device npu
bash /root/smolvla-test-20261020/shared-language/run.sh --device cpu
```

生成阶段的小型索引、因果掩码与 RoPE 的 CPU 兼容计算只作用于测试进程。没有替换 SmolVLA 权重，没有修改 Qwen、驱动或 CANN。


## 复用的意义与限制

共享当前骨干可以省去另一套 Qwen 权重，但仍需要语音识别、语音合成和文本 KV 缓存。整个 SmolVLA 继续常驻时，其视觉/动作参数仍占内存；复用语言不代表完整机器人多任务一定能装入 3.5GB 内存。

若裁剪骨干的问答质量不足，可以评估保留完整语言骨干、让抓取分支仍用前 16 层、文本分支使用完整层数。这样可能共享已有部分权重，但需要另外补齐、核对权重和调整入口；本次未实现，也未测量完整骨干的中文效果。缺少的层若与现有层相同规模，FP16 参数文件约增加 300 MiB，另有激活/缓存等开销，这只是结构估算，不能当作本机内存保证。

另一条路线是保留现有 Qwen 独立问答并按任务调度；最终选择应依据实际回答质量与并发内存，不应仅看模型名称或“里面有语言模型”。
