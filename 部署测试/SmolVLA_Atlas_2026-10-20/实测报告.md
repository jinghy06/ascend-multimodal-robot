# Atlas 200I DK A2：SmolVLA 预训练模型实测

日期：2026-10-20。测试通过以太网 SSH 在用户的实际开发板执行。

**结论：官方预训练 SmolVLA 已在这块 Atlas 的 CPU 与 NPU 路径完成完整动作块推理。NPU 需要兼容处理，首次前向 24.43 s，同一进程第二次前向 4.19 s；当前尚未进行真实机械臂抓取验证。**

## 测试口径

输入为三路确定性渐变图像（各 256×256，模型预处理到 512×512）、6 维零关节状态、英文指令 `pick up the red cup`。状态已视作归一化输入，因此测试中关闭额外 state/action 标准化。噪声由 NumPy seed 42 生成并显式注入，便于跨设备比较。模型使用原配置 10 步去噪，输出未来 50 步、每步 6 维的动作块。

未连接相机采集、未调用电机控制、未实际抓取。本次验证的是模型运行与数值输出，不是任务成功率。输出为归一化动作，不能直接解释为本项目机械臂的角度或位置。

## NPU 完整前向与数值对照

最终运行记录 `smolvla-npu-v13.log` 与 `result_npu_3cam.json`：

| 指标 | 结果 |
|---|---|
| 第一次完整前向（含首轮初始化开销，模型已加载） | 24.4262 s |
| 同一进程第二次完整前向 | 4.1875 s |
| 模型导入、加载至就绪 | 72.13 s |
| 两次前向连同导入与加载的程序总时长 | 102.05 s |
| 输出 | 两次均 `[1,50,6]`，全部数值有限 |
| 进程峰值 RSS | 2275.55 MiB |
| 测试结束状态 | 测试进程退出，NPU Health OK，温度约 51℃ |

路径为 NPU FP16 模型主体 + CPU 图像预处理、bucketize 与小型时间嵌入。计时前后调用 NPU 同步，计时包含模型调用内的 CPU 辅助计算和数据传输。第二次使用 seed 43，第一轮 seed 42 用于 CPU 对照。模型每次重新计算视觉与语言前缀，未跨推理缓存观测特征。

同一 seed 42 噪声下，将 CPU FP32 和 NPU FP16 的全部 300 个输出分量比较（`comparison.json`）：

- 最大绝对误差：0.00286794。
- 平均绝对误差：0.00055589。
- 相对 L2 误差：0.00149106，约 0.149%。
- 余弦相似度：0.99999894。

这组样本数值接近，说明本次兼容路径能保持该样本的动作输出；未形成多场景精度或抓取成功率结论。CPU 只有一次、NPU 只有两次测试，4.19 s 应视为一次暖机后观测值，不是稳定延迟分位数或长期均值。50 步动作块也不代表 50 Hz 闭环控制。当前时延对快速实时抓取仍偏大。


## 在这块板上遇到的兼容问题

1. 系统 Python 原有 torch 版本不足，创建独立环境处理依赖。
2. 默认即时编译会启动多个编译进程，在 3.5GB 内存条件下造成明显交换空间压力。测试限制编译并发并使用 `torch.npu.set_compile_mode(jit_compile=False)`。这只改变当前进程。
3. 图像双线性缩放的 `aclnnUpsampleBilinear2d` 无法直接运行，改为 CPU 图像预处理，再传入 NPU。
4. 当前组合下 GELU、Addmm、SelectV2、SiLU、LinSpace 报缺少算子二进制。兼容路径将 GELU/SiLU 拆为基础函数，将 Linear 拆为矩阵乘加偏置，将有限 FP32 注意力掩码的选择拆为布尔算术。
5. 小型 bucketize 索引运算放在 CPU；小型正弦时间嵌入也放在 CPU 计算，转为 FP32 后传至 NPU，避免 NPU 的 FP64 和 LinSpace 问题。以上修改都在测试进程中生效，未修改系统安装的 LeRobot/Transformers 文件。

这些是对当前驱动、CANN、torch_npu 与输入的实测，不能推出所有 310B 软件版本都不支持对应功能。工具链升级需要完整检查驱动、toolkit、310B kernels 与 torch_npu 的匹配，单独更换一个版本没有可靠保证。

## 复现

模型、配置、环境和脚本均保留在板上。已有环境下执行：

```bash
# CPU 对照（会覆盖同名结果文件）
bash /root/smolvla-test-20261020/run.sh --device cpu --runs 1

# 当前 NPU 兼容路径（会覆盖同名结果文件）
bash /root/smolvla-test-20261020/run.sh --device npu --cpu-preprocess --compat-ops --runs 2
```

`run.sh` 已设置 300 秒上限、离线加载、编译并发限制。CPU 与 NPU 测试应依次运行，避免两个完整模型同时挤占板上内存。测试脚本备份见 `scripts/`；依赖清单用于记录本次组合，不表示完整机器人训练/控制环境已经安装。

基础权重能产生动作块，仍需本项目机械臂的关节定义、坐标标定、相机布置、训练数据与归一化统计匹配，才能评价真实抓取。不能拿合成图像上的有限输出作为“抓取成功”证据。

外部案例和可借鉴经验见 [参考资料](参考资料.md)。这次结果可支持在开题中写“已完成 SmolVLA 基础模型的端侧推理可行性验证，后续优化时延并开展任务适配”，不能写“已实现自主抓取”。对课程项目，建议把 SmolVLA 作为可行的探索路线，抓取主线仍根据实测时延和数据条件决定；若要求实时闭环，需继续优化并测试，或评估已有 310B 部署经验的 ACT / 视觉定位加运动学路线。
